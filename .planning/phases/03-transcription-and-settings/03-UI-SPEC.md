## Color

Distribution contract: 60/30/10 across the workspace and settings shell.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` | App canvas, active note surface, transcript text field area, settings page background |
| Secondary (30%) | `oklch(0.96 0.002 17.2)` | Notes rail, settings section cards, transcript shell, queued/loading states, helper surfaces |
| Accent (10%) | `oklch(0.214 0.009 43.1)` | Active shell mode, `Save Settings`, active transcription mode choice, successful focus/selection emphasis |
| Destructive | `oklch(0.577 0.245 27.325)` | Failed transcript state, invalid settings feedback, clear-credential or destructive confirmation paths only |

Accent reserved for: the active shell view selector, the primary `Save Settings` action, the selected transcription mode, and the strongest selected-note/focus treatments. Never use accent for every field border, every secondary action, or every transcript status.

## Visual Hierarchy

- The desktop shell remains rooted in the current note workspace, but Phase 3 adds one top-level mode switch: `Workspace` and `Settings`.
- `Workspace` keeps the approved two-pane structure from Phase 2: notes rail on the left, active note detail on the right.
- Inside the active note pane, the transcript section becomes the new secondary focal layer between capture and saved media. It should feel more content-rich than metadata fields, but still subordinate to the active note title and capture surface.
- Transcript status is communicated inside the transcript section itself, not as a detached toast or global banner.
- `Settings` is a dedicated full-view panel, not an inline expansion inside the note editor. It should read as three stacked configuration cards: `Storage`, `Transcription`, and `Provider`.
- The `Provider` section appears only when transcription mode is `Backend`.
- Cloud destination choices may appear in the `Storage` section as preferences, but they must feel clearly not-yet-connected in Phase 3. No account picker, sync history, or auth-heavy layout belongs here yet.

---

## Interaction Contract

- A user does not manually start transcription from the media card in Phase 3. Transcript generation starts automatically after a recording or import is saved.
- The transcript section belongs to the active note pane and remains visually separate from the editable note description field.
- Transcript states must render inline in the transcript section:
  - `Queued/processing` uses calm helper styling, not destructive styling.
  - `Succeeded` shows plain text in a read-only presentation block.
  - `Failed` shows the problem inline with a visible retry action.
- Regenerate/retry behavior replaces the existing transcript in place; it does not create version history UI.
- The shell-level `Settings` entry is always reachable without losing the current note selection.
- In `Settings`, changing transcription mode immediately changes which fields are visible:
  - `Local` shows local readiness/download helper copy.
  - `Backend` reveals provider credential fields.
- In `Settings`, choosing storage destination `Local` reveals the local folder picker row. Choosing `Google Drive` or `OneDrive` shows a deferred helper message rather than sync setup.
- Saving settings validates inline and does not require leaving the settings view to discover errors.

## Component Contract

- Use shadcn official blocks only for this phase.
- Preferred official blocks:
  - `button` for shell mode switch actions, `Save Settings`, retry/regenerate, folder pick, and validation recovery actions
  - `card` for transcript section shell and each settings section
  - `tabs` for the top-level `Workspace` / `Settings` shell switch if a segmented shell control is used
  - `radio-group` for transcription mode and storage destination choices
  - `input` for local folder path display and provider key entry
  - `alert` for failed transcript state, invalid settings state, and deferred cloud-helper copy
  - `badge` for transcript status labels such as `Queued`, `Local`, `Backend`, or `Ready`
  - `separator` for division between note content, transcript, and media blocks
- Do not introduce third-party registry blocks for transcript viewers, settings pages, or cloud placeholders in Phase 3.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Shell workspace label | Workspace |
| Shell settings label | Settings |
| Settings primary CTA | Save Settings |
| Transcript section heading | Transcript |
| Transcript empty state | Save audio or video to generate a transcript automatically for this note. |
| Transcript loading state | Generating transcript... Privanote is processing the latest saved media for this note. |
| Transcript failed state | Transcript could not be generated. Check your transcription settings and try again. |
| Retry CTA | Retry Transcript |
| Regenerate CTA | Regenerate Transcript |
| Storage section heading | Storage |
| Transcription section heading | Transcription |
| Provider section heading | Provider |
| Local readiness helper | Local transcription downloads its runtime once and keeps it on this device. |
| Deferred cloud helper | Cloud destinations are preferences only in Phase 3. Upload and sync arrive in Phase 4. |
| Validation error | We couldn't save these settings. Fix the highlighted fields and try again. |
| Destructive confirmation | Clear Credential: Remove the saved backend API key from this device? Transcript jobs in Backend mode will fail until a new key is saved. |

Copy rules:
- Never use bare `Save`, `Submit`, or `Retry` when the surface can be more specific.
- Transcript states must explain both the current status and the next path.
- Deferred cloud copy must explicitly say that the choice is a preference now and that sync comes later.
- Settings errors must be actionable and should not use generic "something went wrong" copy.
