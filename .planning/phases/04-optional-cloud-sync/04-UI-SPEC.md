## Color

Distribution contract: 60/30/10 across the workspace and settings shell.

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `oklch(1 0 0)` | App canvas, active note surface, settings page background, provider forms |
| Secondary (30%) | `oklch(0.96 0.002 17.2)` | Settings section cards, provider connection cards, inline sync helper surfaces, inactive state shelves |
| Accent (10%) | `oklch(0.214 0.009 43.1)` | Active default-destination emphasis, connected-provider badge, synced-status badge, primary connect/reconnect actions, `Save Settings` |
| Destructive | `oklch(0.577 0.245 27.325)` | Failed sync state, disconnect confirmation, destructive connection-clearing paths only |

Accent reserved for: the selected default destination, connected/synced status badges, the main provider `Connect` or `Reconnect` action, and `Save Settings`. Never use accent for every outlined button, every provider row, or every media-card control.

## Visual Hierarchy

- `Settings` becomes the command center for Phase 4 cloud setup, but it remains subordinate to the note workspace. The shell still opens into `Workspace`.
- Inside `Settings`, the user should scan in this order: `Default destination`, `Provider connection state`, then `sync policy helper copy`.
- Each provider card must show connection state and default-destination state separately. A provider can be `Connected` without being the active default.
- In the note workspace, the media preview remains the primary anchor on each saved media card. Sync state is a compact secondary layer near the save metadata, not a detached panel below the card.
- Failed sync should read as a contained inline problem on the media card, never as a global app error. The card must still visually communicate that the local media remains usable.
- Transcript-sync follow-up state belongs near the sync badge cluster as compact helper text, not as a second full-width alert block.

---

## Interaction Contract

- Provider connection and disconnect flows live only in `Settings`.
- Users may connect both Google Drive and OneDrive, but the UI must always communicate one active default destination for automatic sync.
- A cloud provider cannot become the default destination until it is connected. Unconnected cloud options should route the user toward `Connect Google Drive` or `Connect OneDrive` instead of silently accepting an unusable default.
- Changing the default destination must explain the consequence inline: future saves and older unsynced local attachments will queue to the newly selected provider.
- Changing the default destination must not imply migration of items already synced to another provider.
- Media cards support only compact sync states in Phase 4:
  - `Local only`
  - `Syncing`
  - `Synced to Google Drive` or `Synced to OneDrive`
  - `Sync failed`
- If media uploads before transcript generation finishes, the card keeps the primary sync badge compact and adds one line of helper status such as transcript/metadata pending rather than a second badge system.
- Sync failure never disables local playback, open-file, or remove actions.
- Retry actions stay on the media card. Users should not need to visit `Settings` to retry a failed attachment sync.
- Disconnecting a provider requires confirmation copy that explicitly says remote files stay in the provider account.

---

## Component Contract

- Use shadcn official blocks only for this phase.
- Preferred official blocks:
  - `button` for provider connect, reconnect, disconnect, retry sync, and `Save Settings`
  - `card` for provider connection sections and media-card sync state containers
  - `tabs` for the existing `Workspace` / `Settings` shell switch if retained
  - `radio-group` for selecting the default sync destination
  - `badge` for `Connected`, `Default`, `Local only`, `Syncing`, `Synced`, and `Sync failed`
  - `alert` for inline sync-failure messaging and disconnect confirmation copy
  - `separator` for dividing provider sections from default-destination policy copy
  - `input` only for read-only account or destination metadata if a field treatment is needed
- Do not introduce third-party registry blocks for sync dashboards, provider auth widgets, or cloud file browsers in Phase 4.

## Copywriting Contract

| Element | Copy |
|---------|------|
| Settings cloud heading | Cloud sync |
| Primary CTA | Connect Google Drive |
| Mirrored provider CTA | Connect OneDrive |
| Save settings CTA | Save Settings |
| Empty state heading | Optional cloud sync |
| Empty state body | Connect Google Drive or OneDrive in Settings to sync future saves while keeping every attachment on this device. |
| Default destination helper | Future saves and older unsynced local media will queue to the selected destination. Already-synced items stay where they are. |
| Connected badge | Connected |
| Default badge | Default destination |
| Local-only badge | Local only |
| Syncing badge | Syncing |
| Synced badge | Synced to Google Drive / Synced to OneDrive |
| Transcript pending helper | Media uploaded. Transcript and metadata will sync when ready. |
| Failed badge | Sync failed |
| Failed state | Sync failed. Your local file is still available. Retry sync or reconnect this provider in Settings. |
| Retry CTA | Retry Sync |
| Disconnect confirmation | Disconnect Provider: Remove this provider connection from Privanote? Existing remote files stay in your account, and local attachments remain available here. |

Copy rules:
- Never use bare `Connect`, `Retry`, or `Disconnect` when the provider or object can be named more clearly.
- Every sync failure message must explicitly preserve the user's confidence in the local copy.
- Default-destination copy must distinguish `connected` from `default`.
- Do not describe Phase 4 sync as backup-only or cloud-primary. The copy must reinforce local-first behavior.
