# Phase 6 — UI Design Contract

> Visual and interaction contract for the always-on-top floating capture button and its integration with the main Privanote window. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (main window only; overlay is standalone) |
| Preset | radix-nova, baseColor: taupe, cssVariables: true |
| Component library | radix-ui via shadcn (main window); none (overlay) |
| Icon library | lucide-react (main window); inline SVG (overlay) |
| Font | Inter Variable via @fontsource-variable/inter (main window); system-ui (overlay) |

The floating overlay window is a separate HTML entry point (`capture-overlay.html`) with its own tiny CSS. It does NOT load shadcn, Tailwind, or Inter Variable. It uses inline styles and system-ui to minimize load time and bundle size.

Source: RESEARCH.md architecture pattern (separate entry point); CONTEXT.md locked decision (tiny overlay, not full App.jsx).

| Token | Value | Usage |

| sm | 8px | Permission dialog paragraph spacing |

| lg | 24px | Session summary section padding in main window |
| xl | 32px | Not used in this phase |
| 2xl | 48px | Not used in this phase |

Exceptions:
- Floating overlay window size: 56px diameter circular button inside a 64x64px BrowserWindow (non-standard, matches RESEARCH.md recommendation)

Source: RESEARCH.md Pattern 1 (64x64 window), Pattern 4 (56px button with drag region).

## Typography

The floating overlay has no visible text in idle or recording states (icon-only). Typography applies only to the main window surfaces introduced in this phase.

| Role | Size | Weight | Line Height |
|------|------|--------|-------------|
| Body | 14px (`text-sm`) | 400 (regular) | 1.5 (`leading-[21px]`) |
| Label | 14px (`text-sm`) | 600 (`font-semibold`) | 1.0 (single line) |
| Heading | 20px (`text-xl`) | 600 (`font-semibold`) | 1.2 (`leading-[1.2]`) |

Notes:
- Only 3 sizes needed. No Display size is introduced in this phase.
- Two weights only: 400 and 600. Consistent with Phase 5 contract.
- Session summary heading uses Heading role. App name labels in grouped captures use Label role. Extracted text blocks use Body role.
- The overlay window itself contains zero text. State is communicated entirely through icon shape and color.

Source: Phase 5 UI-SPEC typography table (continuity); CONTEXT.md (icon-only button states).

## Layout Contract

### Floating Overlay Window

```
BrowserWindow (64x64, transparent, frameless, always-on-top)
  <div class="capture-overlay-root">
    <div class="capture-button-container" style="-webkit-app-region: drag">
      <button class="capture-button" style="-webkit-app-region: no-drag">
        [Icon: idle=Camera/Video, recording=Square(stop)]
        [Pulse ring: recording state only]
      </button>
    </div>
  </div>
```

- The outer `div` is draggable (`-webkit-app-region: drag`) so the user can reposition the button.
- The inner `button` is `no-drag` so clicks register as click events, not drag starts.
- Initial position: top-right corner of primary display, 80px from right edge, 80px from top edge.
- The window is `focusable: false` so clicking it does not steal focus from the user's active app.
- The window is visible on all workspaces including fullscreen (`setVisibleOnAllWorkspaces(true, { visibleOnFullScreen: true })`).

### Main Window — Permission Dialog

When the user clicks the overlay button but required permissions are missing, a dialog surfaces in the main Privanote window (not in the overlay).

```
<aside> (existing sidebar)
  [Capture Panel]        -- existing, unchanged
  [Permission Banner]    -- NEW: appears at top of sidebar when permissions missing
  [Notes Section]        -- existing, unchanged
</aside>
```

The permission banner is a compact inline alert, not a modal. It appears between the capture panel and the notes section header.

### Main Window — Session Note Detail

After a capture session ends, a note is auto-created and selected. The note detail panel shows:

```
<section> (existing right panel)
  [Note title]           -- Auto-generated: "{App1, App2} session -- {date} {time}"
  [Note description]     -- Editable, initially empty
  [Session metadata]     -- Duration, apps captured, capture count
  [App Group 1]          -- App name heading + extracted text blocks + screenshot cards
  [App Group 2]          -- Same structure, next app
  ...
  [Transcript Section]   -- Only if audio was captured during session
</section>
```

Source: CONTEXT.md (note creation format, group by source app); RESEARCH.md (Pattern 2 session state machine).

## Interaction Contract

| Interaction | Trigger | Result |
|-------------|---------|--------|
| Start capture session | Click overlay button (idle) OR press Cmd+Shift+R | Overlay transitions to recording state (red fill + pulse animation). Main process begins event-driven screenshot capture. |
| Stop capture session | Click overlay button (recording) OR press Cmd+Shift+R | Overlay transitions to finalizing state (muted fill, spinner icon). Main process groups captures by app, creates note, uploads screenshots. Overlay returns to idle when complete. |
| Drag overlay | Click and drag on the button container (not the button itself) | Overlay window repositions. New position persists for the session (not across relaunch in v1). |
| Permission missing | Click overlay button when Screen Recording or Accessibility is not granted | Overlay stays idle. Main window shows permission banner in sidebar with CTA to open System Settings. |
| Permission granted | User grants permission in System Settings and returns to Privanote | Permission banner auto-dismisses on next permission check. Overlay becomes functional. |
| Session note created | Capture session finalized | Main window auto-selects the new note in the sidebar notes list. Right panel shows session note detail with grouped captures. |
| Window focus change during capture | User switches between apps while session is recording | Main process captures a screenshot and extracts text from the newly focused app. Each capture is tagged with app name and window title. |
| Hover overlay (idle) | Mouse enters overlay button area | Button fill lightens to hover color. Cursor shows pointer. |
| Hover overlay (recording) | Mouse enters overlay button area | No color change (already red). Cursor shows pointer. |

Source: CONTEXT.md (two states, click toggle, event-driven capture); RESEARCH.md (Pattern 2 state machine, Pattern 3 event-driven capture).

## Overlay Visual Specification

### Idle State
- Circle: 56px diameter, centered in 64x64 window
- Fill: `oklch(0.214 0.009 43.1)` (primary)
- Icon: Camera outline, 24px, white (`oklch(0.986 0.002 67.8)`)
- Border-radius: 50%
- Box-shadow: `0 2px 8px rgba(0, 0, 0, 0.24)` (drop shadow for visibility over any background)
- Transition: `background-color 150ms ease, transform 150ms ease`
- Hover: fill lightens to `oklch(0.35 0.012 43.1)`, `transform: scale(1.06)`

### Recording State
- Circle: 56px diameter (same size)
- Fill: `oklch(0.577 0.245 27.325)` (destructive red)
- Icon: Square (stop), 20px, white (`oklch(1 0 0)`)
- Pulse animation: outer ring expands from 56px to 72px, opacity fades from 40% to 0%, repeats every 1.5s with `ease-out`
- Box-shadow: `0 2px 12px rgba(220, 50, 50, 0.35)` (red-tinted shadow)

### Finalizing State
- Circle: 56px diameter (same size)
- Fill: `oklch(0.547 0.021 43.1)` (muted foreground)
- Icon: Spinning loader, 20px, white
- No pulse animation
- Duration: typically 1-3 seconds while note is created

### CSS for Pulse Animation (overlay standalone CSS)
```css
@keyframes capture-pulse {
  0% {
    transform: scale(1);
    opacity: 0.4;
  }
  100% {
    transform: scale(1.29);
    opacity: 0;
  }
}

.capture-pulse-ring {
  animation: capture-pulse 1.5s ease-out infinite;
  background: oklch(0.577 0.245 27.325);
  border-radius: 50%;
  position: absolute;
  inset: 0;
  pointer-events: none;
}
```

Source: CONTEXT.md (idle icon, red pulsing recording indicator); RESEARCH.md Pattern 4 (drag CSS).
