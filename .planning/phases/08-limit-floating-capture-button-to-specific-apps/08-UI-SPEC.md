## Focal Point

The toggle switches on each app row are the primary interaction focal point. They are right-aligned within each row, providing a consistent vertical axis for the user's eye to scan. The accent color on the toggle on-state draws attention to enabled apps.

## Component Inventory

This phase adds one new settings section and modifies overlay visibility logic. No new standalone components are created.

### New: Capture Apps Settings Section

Location: Inside existing `SettingsView` component, after the Transcription section and before the Save Settings button.

#### Structure

```
<div class="grid gap-6 rounded-[28px] bg-secondary/70 p-6">   <!-- card wrapper, matches existing sections -->
  <div class="space-y-1">                                       <!-- header -->
    <h3>Capture apps</h3>
    <p>description</p>
  </div>
  <div class="grid gap-4">                                      <!-- app list: 16px between rows -->
    <!-- 5 app rows, one per preset -->
  </div>
</div>
```

#### App Row Layout

Each of the 5 preset apps renders as a row:

```
<label class="flex items-center justify-between gap-2 rounded-2xl border bg-background px-4 py-2">
  <div class="flex items-center gap-2">
    <span class="text-sm font-semibold">{App Name}</span>
    <span class="text-sm text-muted-foreground">{detection hint}</span>
  </div>
  <toggle />   <!-- shadcn Switch or native checkbox styled as toggle -->
</label>
```

Spacing rationale: `gap-2` (8px) for inline element spacing within a row, `py-2` (8px) for compact vertical padding, `px-4` (16px) for horizontal padding, `gap-4` (16px) for spacing between rows in the app list. All values are from the declared spacing scale.

| App | Label | Detection Hint |
|-----|-------|----------------|
| Slack | Slack | Desktop app |
| Gmail | Gmail | mail.google.com |
| Notion | Notion | Desktop or browser |
| Jira | Jira | atlassian.net |
| GitHub | GitHub | github.com |

#### Toggle Control

Use a native `<input type="checkbox">` styled as a toggle switch, consistent with the radio-button pattern already used in settings-view.jsx. Alternatively, if a shadcn Switch component is already installed, use that.

- **Off state:** Track uses `var(--border)` background, thumb uses `var(--background)`.
- **On state:** Track uses `var(--primary)` background, thumb uses `var(--primary-foreground)`.
- **Dimensions:** 40px wide, 24px tall track. 20px diameter thumb.
- **Transition:** 150ms ease on background-color and transform.
- **Disabled state:** opacity 0.5, cursor not-allowed (when isLoading or isSaving).

### Existing: Capture Overlay (no visual change)

The floating overlay button retains its current 56px circular design. This phase only changes its visibility (show/hide) based on the active app whitelist. No CSS or layout changes to the overlay itself.

### Existing: Settings View (structural addition only)

The existing `SettingsView` component gains one new section. The existing card pattern (`rounded-[28px] bg-secondary/70 p-6`) is reused exactly.

## Interaction Contract

### Overlay Show/Hide Behavior

| Trigger | Behavior |
|---------|----------|
| App switch to whitelisted app | Overlay appears instantly (no animation) via `captureOverlay.show()` |
| App switch to non-whitelisted app | Overlay hides instantly (no animation) via `captureOverlay.hide()` |
| All toggles off (whitelist empty) | Overlay stays hidden at all times |
| Active capture session in progress | Overlay remains visible regardless of active app (D-08) |
| User toggles an app on in settings | Takes effect on next polling cycle, no app restart needed |
| User toggles an app off in settings | Takes effect on next polling cycle; if currently showing for that app, hides on next check |

### Settings Toggle Behavior

| Action | Result |
|--------|--------|
| Toggle app on | App added to `captureApps` whitelist in settings state |
| Toggle app off | App removed from `captureApps` whitelist in settings state |
| Save Settings | Whitelist persisted to backend; main process reloads whitelist |
| Settings load | Toggle states reflect current persisted whitelist |

## Copywriting Contract

| Element | Copy |
|---------|------|
| Section heading | Capture apps |
| Section description | Choose which apps trigger the floating capture button. The button appears only when a selected app is in the foreground. |
| Empty state (all off) | No apps selected. The capture button will stay hidden until you enable at least one app. |
| Error state | Could not save capture app preferences. Check your settings and try again. |
| Primary CTA | Save Settings (shared with existing settings view, not a new button) |

No destructive actions exist in this phase.

## States Summary

| State | Visual |
|-------|--------|
| All toggles off | Section description visible, info text below toggles: "No apps selected..." in `text-sm text-muted-foreground` |
| One or more toggles on | Enabled toggles show primary-colored track |
| Settings loading | All toggles disabled (opacity 0.5) |
| Settings saving | All toggles disabled (opacity 0.5) |
| Settings save error | Error banner in `rounded-2xl border border-destructive/20 bg-destructive/10` (existing pattern) |
