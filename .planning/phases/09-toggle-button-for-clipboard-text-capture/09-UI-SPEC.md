# Phase 9 — UI Design Contract

> Visual and interaction contract for the clipboard text capture toggle button on the floating overlay. Generated by gsd-ui-researcher, verified by gsd-ui-checker.

---

## Design System

| Property | Value |
|----------|-------|
| Tool | shadcn (overlay is self-contained HTML — no shadcn components used in this surface) |
| Preset | radix-nova / taupe / cssVariables / oklch |
| Component library | N/A for overlay — self-contained HTML with inline styles matching shadcn tokens |
| Icon library | Lucide (SVG inline in overlay HTML) |
| Font | Inter Variable (not loaded in overlay — system font stack used for badge text) |

**Note:** The floating overlay (`capture-overlay.html`) is a self-contained HTML file with inline CSS. It does not use Tailwind or shadcn components. All new elements must follow the same inline-style pattern using oklch color values from the design system tokens.

## Spacing Scale

Declared values (must be multiples of 4):

| Token | Value | Usage |
|-------|-------|-------|
| xs | 4px | Gap between badge and button edge |
| sm | 8px | Gap between capture button and clipboard button |
| md | 16px | Not used in overlay |
| lg | 24px | SVG icon size inside buttons |
| xl | 32px | Not used in overlay |
| 2xl | 48px | Not used in overlay |
| 3xl | 64px | Overlay container width/height per button column |

Exceptions:
- Overlay container body expands from `64x64` to `64x136` to accommodate two vertically stacked buttons (64px per button slot + 8px gap)
- Button diameter remains 56px (existing pattern)
- Badge diameter is 20px (minimum readable size for counter text)
- Touch target minimum 44px is satisfied by the 56px button

## Color

| Role | Value | Usage |
|------|-------|-------|
| Dominant (60%) | `transparent` | Overlay body background |
| Secondary (30%) | `oklch(0.214 0.009 43.1)` | Button idle background (both capture and clipboard) |
| Accent (10%) | `oklch(0.488 0.243 264.376)` | Clipboard monitoring active state background |
| Destructive | `oklch(0.577 0.245 27.325)` | Screen capture recording state only (existing) |

Accent reserved for: Clipboard button active/monitoring state background only. The blue accent (`oklch(0.488 0.243 264.376)` — sidebar-primary from dark theme) distinguishes clipboard monitoring from screen capture recording (red/destructive). This gives each feature a distinct color identity.

### Button State Colors

| State | Capture Button | Clipboard Button |
|-------|---------------|-----------------|
| Idle | `oklch(0.214 0.009 43.1)` (dark taupe) | `oklch(0.214 0.009 43.1)` (dark taupe) |
| Hover | `oklch(0.35 0.012 43.1)` (lighter taupe) | `oklch(0.35 0.012 43.1)` (lighter taupe) |
| Active/Recording | `oklch(0.577 0.245 27.325)` (red) | `oklch(0.488 0.243 264.376)` (blue) |
| Finalizing | `oklch(0.547 0.021 43.1)` (muted) | N/A — clipboard creates note instantly |

## Component Inventory

### New Elements (added to capture-overlay.html)

1. **Clipboard toggle button** (`.btn.clipboard`)
   - 56px diameter circle, identical shape to existing capture button
   - Positioned below the capture button with 8px vertical gap
   - Icon: Lucide `clipboard-copy` SVG (idle) / `clipboard-check` SVG (monitoring) / spinner SVG (finalizing)
   - Click toggles clipboard monitoring on/off
   - `aria-label`: "Start clipboard monitoring" (idle) / "Stop clipboard monitoring" (active)

2. **Badge counter** (`.badge`)
   - 20px diameter circle, positioned top-right of clipboard button (-4px offset from edge)
   - Shows live count of captured clipboard entries
   - Hidden when count is 0 or monitoring is idle
   - Text: entry count (e.g., "3", "12")
   - For counts > 99, display "99+"
   - `aria-live="polite"` for screen reader announcements

3. **Pulse ring for clipboard** (`.pulse.clipboard-pulse`)
   - Same animation as existing capture pulse but using blue accent color
   - `oklch(0.488 0.243 264.376)` instead of red
   - Visible only during active clipboard monitoring

### Modified Elements

4. **Overlay container** (`.container`)
   - Changes from `64x64` to `64x136` (two buttons stacked vertically)
   - `flex-direction: column` with `gap: 8px`
   - Body dimensions update accordingly: `width: 64px; height: 136px`

5. **Overlay BrowserWindow** (in main.js)
   - Window dimensions change from `64x64` to `64x136`

### Interaction States

| Interaction | Clipboard Button Behavior |
|-------------|--------------------------|
| Click (idle) | Start monitoring -> blue background, pulse, badge appears at "0" then increments |
| Click (monitoring) | Stop monitoring -> create note, return to idle |
| Click (finalizing) | Disabled, spinner icon, cursor: default |
| Hover (idle) | Scale 1.06, lighter background (same as capture hover) |
| Hover (monitoring) | No additional hover effect (active state is prominent enough) |

### IPC Bridge Methods (preload)

| Method | Direction | Purpose |
|--------|-----------|---------|
| `window.captureApi.startClipboard()` | renderer -> main | Start clipboard monitoring |
| `window.captureApi.stopClipboard()` | renderer -> main | Stop monitoring, create note |
| `window.captureApi.getClipboardState()` | renderer -> main | Get current state on overlay load |
| `window.captureApi.onClipboardStateChange(cb)` | main -> renderer | State updates: idle/monitoring/finalizing |
| `window.captureApi.onClipboardCount(cb)` | main -> renderer | Live entry count updates |
