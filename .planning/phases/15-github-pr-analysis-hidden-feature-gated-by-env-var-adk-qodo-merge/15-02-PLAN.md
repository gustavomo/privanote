    **adapters/github_adapter.py** (per D-06, D-31, D-34, D-46):
    Create a class `GitHubAdapter(GitHubPort)` that takes `token: str` in the constructor. Uses `httpx.AsyncClient` with `Authorization: Bearer {token}` header and base URL `https://api.github.com`.

    Methods:
    - `async def get_pr_metadata(self, owner, repo, number) -> PRMetadata`: 
      - GET `/repos/{owner}/{repo}/pulls/{number}` for PR data
      - GET `/repos/{owner}/{repo}/pulls/{number}/files` for changed files (handle pagination via Link header)
      - Map JSON response to PRMetadata Pydantic model
      - On 404: raise `ValueError("Cannot access repo -- check GITHUB_TOKEN permissions")` (per D-31)
      - On 403 with rate limit: raise `ValueError("GitHub API rate limit reached. Try again in X minutes.")` where X = `int(response.headers.get('x-ratelimit-reset', 0)) - time.time()` rounded to minutes (per D-34)
    
    - `async def get_review_comments(self, owner, repo, number) -> list[dict]`:
      - GET `/repos/{owner}/{repo}/pulls/{number}/comments` for line-level review comments
      - GET `/repos/{owner}/{repo}/issues/{number}/comments` for general issue/PR comments (includes CodeRabbit, Copilot, human)
      - GET `/repos/{owner}/{repo}/pulls/{number}/reviews` for review-level comments
      - Return combined list of `ReviewComment` dicts with author, body, created_at, url
      - Handle pagination for all endpoints

    Internal helper `async def _paginated_get(self, url: str) -> list[dict]`:
      - Follow GitHub `Link: <url>; rel="next"` pagination headers
      - Collect all pages into a single list

    **adapters/note_callback.py** (per D-47, D-21):
    Create a class `NoteCallbackAdapter(NoteCallbackPort)` that takes `callback_url: str` in the constructor. 
    
    Method `async def send_analysis_result(self, result: dict) -> dict`:
    - POST to `self._callback_url` with JSON body containing the analysis result
    - Use `httpx.AsyncClient` with 30s timeout
    - On success (2xx): parse and return the response JSON (expected shape: `{"success": True, "nodeId": "..."}`)
    - The returned dict is critical -- the pipeline uses `response["nodeId"]` to store the created note's ID in the job result, enabling auto-select in the main window (D-21)
    - On non-2xx response: raise `RuntimeError(f"Note callback failed: {response.status_code}")`

    **adapters/qodo_adapter.py** (per D-09, D-11, D-03):
    Create a class `QodoAdapter(CodeReviewPort)` that takes `github_token: str` and `openai_api_key: str` in the constructor.

    Key implementation details:
    - Import `from pr_agent.config_loader import get_settings` and `from pr_agent import cli`
    - Each method must set Qodo global settings fresh before each call (per Pitfall 6: settings contamination):
      ```python
      def _configure_qodo(self) -> None:
          settings = get_settings()
          settings.set("CONFIG.git_provider", "github")
          settings.set("openai.key", self._openai_api_key)
          settings.set("github.user_token", self._github_token)
      ```
    - Wrap synchronous pr-agent calls with `asyncio.to_thread()` (per Pitfall 2: sync blocking):
      ```python
      result = await asyncio.to_thread(cli.run_command, pr_url, "/review")
      ```

    Methods:
    - `async def review(self, pr_url: str) -> CodeReviewResult`:
      - Call `cli.run_command(pr_url, "/review")` via `asyncio.to_thread`
      - Parse the result into `CodeReviewResult` model
      - If pr-agent returns a string, store it as `raw_output`
      - If pr-agent returns structured data, map to `CodeReviewFinding` objects
      - On exception: re-raise with context `f"Qodo review failed: {e}"`

    - `async def describe(self, pr_url: str) -> PRDescription`:
      - Call `cli.run_command(pr_url, "/describe")` via `asyncio.to_thread`
      - Parse result into `PRDescription` model with summary and categorized changes
      - Store raw output regardless of parsing success

    - `async def improve(self, pr_url: str) -> list[ImprovementSuggestion]`:
      - Call `cli.run_command(pr_url, "/improve")` via `asyncio.to_thread`
      - Parse result into list of `ImprovementSuggestion` objects
      - Store raw output in each suggestion's `raw_output` field

    Note: The exact return format of `cli.run_command()` is under-documented (per RESEARCH.md Open Question 2). The adapter should handle both string and dict return types gracefully, storing raw output when structured parsing fails.
