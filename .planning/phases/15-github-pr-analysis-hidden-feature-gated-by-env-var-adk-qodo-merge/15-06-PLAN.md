    For completion (per D-21, UI-SPEC):
    ```javascript
    useEffect(() => {
      if (!window.api?.onPrAnalysisComplete) return;
      const cleanup = window.api.onPrAnalysisComplete((data) => {
        // Success toast (per UI-SPEC: title "PR analysis complete", description truncated to 60 chars)
        const description = data.title
          ? (data.title.length > 60 ? data.title.slice(0, 57) + '...' : data.title)
          : 'Analysis complete';
        toast.success('PR analysis complete', { description, duration: 5000 });

        // Auto-select the new note (per D-21)
        if (data.nodeId) {
          loadNodes().then(() => {
            setSelectedNodeId(data.nodeId);
          });
        } else {
          loadNodes();
        }
      });
      return cleanup;
    }, []);
    ```

    For error:
    ```javascript
    useEffect(() => {
      if (!window.api?.onPrAnalysisError) return;
      const cleanup = window.api.onPrAnalysisError((data) => {
        toast.error('PR analysis failed', {
          description: data.error || 'Analysis failed. Retry from the overlay button.',
          duration: 8000,
        });
      });
      return cleanup;
    }, []);
    ```

    **IMPORTANT:** The `toast` import from `sonner` must already exist in App.jsx (added in Phase 14).     **main.js adjustment:**
    Verify that the `pr:analysis-complete` event sent from main.js includes the `nodeId` of the created note. The note is created by the Python callback hitting `/internal/pr-callback`, which returns `{ success: true, nodeId: node.id }`. But the polling status check (`getAnalysisStatus`) may not have the nodeId.

    To fix this: In `routes/internal.js`, return the nodeId in the response. The Python pipeline stores it in the job result. The polling picks it up from `status.result.nodeId`.

    For this to work, the Python `NoteCallbackAdapter.send_analysis_result()` must capture the response `{ success, nodeId }` and store `nodeId` in the job result. This is already handled if the pipeline stores the callback response. If not, the main process polling can fall back to refreshing the notes list without auto-selecting.

    **Fallback approach if nodeId not available:** On completion, just call `loadNodes()` without auto-selecting. The newest note (github-analysis tagged) will be at the top of the list. The user can click it.
