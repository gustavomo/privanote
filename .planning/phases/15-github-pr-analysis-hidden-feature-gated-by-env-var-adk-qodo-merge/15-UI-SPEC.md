## Component Inventory

### Overlay: 4th Button (PR Analysis)

**Location:** `capture-overlay.html` -- new button added below the call recording button in the DOM order.

**Visibility rule:** Appears when `PRIVANOTE_PR_ANALYSIS=true` AND active app is a supported browser AND current URL matches `github.com/{owner}/{repo}/pull/{number}`. Hidden otherwise. Uses the same conditional visibility pattern as `#btn` (screen capture) and `#callBtn` (call recording).

**States:**

| State | CSS Class | Background | Icon | Title/Aria-Label |

| idle | `.btn.visible` | `oklch(0.214 0.009 43.1)` | git-pull-request (closed/slashed) | "Analyze this PR" |

| finalizing | `.btn.pr-finalizing.visible` | `oklch(0.547 0.021 43.1)` | spinner | "Creating note..." |
| disabled | `.btn.disabled.visible` | inherited + `opacity: 0.35` | git-pull-request (closed) | "PR analysis unavailable" |

### Overlay: URL Input Popover

**Trigger:** Clicking the idle PR button opens a small popover instead of immediately starting analysis. This allows the user to confirm or edit the auto-detected URL before proceeding.

**Layout:**
- Width: 280px
- Background: `oklch(0.214 0.009 43.1)` (matches overlay button idle background for visual consistency)
- Border-radius: 8px
- Box-shadow: `0 2px 12px rgba(0, 0, 0, 0.32)`
- Padding: 8px
- Position: anchored to the left of the PR button, offset 8px horizontally

**Contents (top to bottom):**

1. **URL input field**
   - Full-width text input
   - Height: 32px
   - Font: system font, 14px, weight 400
   - Background: `oklch(0.30 0.008 43.1)`
   - Border: 1px solid `oklch(0.40 0.01 43.1)`
   - Border-radius: 6px
   - Text color: `oklch(0.95 0 0)` (near-white)
   - Placeholder: "github.com/owner/repo/pull/123"
   - Placeholder color: `oklch(0.55 0.01 43.1)`
   - Auto-populated with detected PR URL when available
   - Focus ring: 2px solid `oklch(0.65 0.15 195)` (teal accent)

2. **Validation error text** (conditional)
   - Font: system font, 12px, weight 400
   - Color: `oklch(0.75 0.18 25)` (warm red, readable on dark background)
   - Margin-top: 4px
   - Copy: "Enter a valid GitHub PR URL"
   - Shown only when input does not match `github.com/{owner}/{repo}/pull/{number}`

3. **Action row** (horizontal, right-aligned)
   - Margin-top: 8px
   - Gap: 8px between buttons

   **Dismiss button:**
   - Width: auto, padding: 4px 12px
   - Height: 28px
   - Font: system font, 12px, weight 400
   - Background: transparent
   - Color: `oklch(0.70 0.01 43.1)`
   - Border: none
   - Border-radius: 4px
   - Hover: `background: oklch(0.30 0.008 43.1)`
   - Label: "Dismiss"

   **Analyze PR button:**
   - Width: auto, padding: 4px 12px
   - Height: 28px
   - Font: system font, 12px, weight 600
   - Background: `oklch(0.65 0.15 195)` (teal accent)
   - Color: white
   - Border: none
   - Border-radius: 4px
   - Hover: `background: oklch(0.70 0.15 195)`
   - Disabled state: `opacity: 0.5; pointer-events: none` (when URL is invalid)
   - Label: "Analyze PR"

**Dismiss:** Clicking Dismiss, pressing Escape, or clicking outside the popover closes it.

**Overlay resize:** When popover is visible, overlay window width expands from 48px to accommodate 48px (buttons) + 8px (gap) + 280px (popover) = 336px. Height remains based on button count. `resizeOverlay` IPC call adjusts the BrowserWindow dimensions. Popover is positioned to the left of the button column using `position: absolute`.

### Overlay: Status Text During Analysis

**Location:** Small text label below the PR button, inside the overlay container.

**States:**

| Job Phase | Text | Color |
|-----------|------|-------|
| Starting | "Analyzing..." | `oklch(0.65 0.15 195)` |
| Fetching reviews | "Fetching reviews..." | `oklch(0.65 0.15 195)` |
| Generating note | "Generating note..." | `oklch(0.65 0.15 195)` |

**Typography:**
- Font: system font, 9px, weight 600
- Letter-spacing: 0.02em
- Text-align: center
- Width: 48px (contained within button column)
- Overflow: hidden, text-overflow: ellipsis, white-space: nowrap

**Height recalculation:** Status text adds 16px to the overlay height when visible (4px top padding + 9px text + 4px bottom padding = 17px, rendered as 16px total allocation with 4px vertical padding around the 9px text line).

### Main Window: Sonner Toast on Completion

Uses the existing `Sonner` component from `sonner.jsx` at `bottom-right` position.

**Success toast:**
- Type: `toast.success()`
- Title: "PR analysis complete"
- Description: `{PR title} -- {owner/repo}#{number}` (truncated to 60 chars with ellipsis)
- Duration: 5000ms
- Action: none (note auto-selected in sidebar)

**Error toast:**
- Type: `toast.error()`
- Title: "PR analysis failed"
- Description: Specific error message from backend:
  - "Cannot access repo -- check GITHUB_TOKEN permissions" (D-31)
  - "GitHub API rate limit reached. Try again in X minutes." (D-34)
  - "Analysis failed. Retry from the overlay button." (generic)
- Duration: 8000ms (longer for error reading)

**No new shadcn components required.** Toast uses existing Sonner integration.

### Main Window: Note Display

The generated PR analysis note follows the existing note display pattern -- no new UI components needed. The note body contains markdown with Mermaid code blocks that render as plain code (per D-24: raw Mermaid stored, rendered when markdown rendering is added later).

**Tag rendering:** The `github-analysis` tag uses the existing Badge component with default variant. No special tag styling.

## Interaction Contracts

### Button Appearance Trigger

1. Main process detects `PRIVANOTE_PR_ANALYSIS=true` at startup
2. App whitelist polling (500ms, existing) detects a supported browser is active
3. AppleScript URL extraction (existing Phase 8 pattern) detects a URL matching `github.com/{owner}/{repo}/pull/{number}`
4. Main process sends IPC `pr:url-detected` with `{ url, owner, repo, number }` to overlay
5. Overlay shows the 4th button with idle state and stores the URL

### Analysis Flow

1. User clicks idle PR button -> URL input popover opens with auto-detected URL pre-filled
2. User confirms or edits URL, clicks "Analyze PR"
3. Popover closes, button transitions to `pr-analyzing` state, status text appears
4. Overlay sends IPC `pr:start-analysis` with `{ url }` to main process
5. Main process forwards to Node.js backend `POST /api/v1/analyze/pr`
6. Main process polls `GET /api/v1/analyze/pr/:id` for status updates
7. Status updates sent to overlay via IPC `pr:status-update` with `{ phase }` (maps to status text)
8. On completion: main process sends IPC to renderer for Sonner toast + auto-selects note
9. Main process sends `pr:analysis-complete` to overlay, button returns to idle
10. On error: main process sends `pr:analysis-error` to overlay with error message, button returns to idle, error toast in main window

### Mutual Exclusion

The PR analysis button has NO mutual exclusion with other overlay buttons. Screen capture, clipboard monitoring, and call recording can all run simultaneously with a PR analysis. The analysis is a background HTTP request, not a media capture operation.

### Keyboard

No new keyboard shortcuts for this phase. The PR button is click-only from the overlay. The URL input field supports standard text editing (Cmd+A, Cmd+V, Cmd+C) and Enter to submit, Escape to dismiss.
